I read a lot. Articles, papers, repos, random Medium posts at 1am. And most of that
was dying in browser tabs instead of landing in my [PKM](https://github.com/BorjaIP/pkm).

So I built [AI Web](https://github.com/BorjaIP/obsidian-ai-web), a small Obsidian plugin
that takes a URL and writes a structured note straight into my vault. Not a chatbot
inside Obsidian — I don't want to talk to it, I want it to file my reading for me.

## How it goes

One command (`Create a Note from web`), a modal with three fields — note name, URL and
type (article, paper or code) — and that's the whole UI.

Under the hood it's not one big prompt. It's a set of small operators, each one a clean
AI call: summarize, extract tags, detect type, validate URLs, pull real references.
Small calls are cheaper, easier to debug and each one can be improved on its own.
Right now the generate flow fires the summary and the tags calls in parallel and merges
both into the note.

## The note it writes

Everything lands in `articles/webs/` with frontmatter and fixed sections: link, source,
a 100-word summary, the 5 main points and a references list. The prompt explicitly
forbids hallucinated links — references only if they are real and known.

This is an actual note from my vault:

```markdown
---
title: Storage Orchestration for Kubernetes
created: Saturday 3rd May 2025 00:04
tags:
  - "#aiweb"
  - "#aiweb-gpt-4o"
  - medium
  - "#k8s"
  - "#storage-orchestration"
---
- Link: [Storage Orchestration for Kubernetes](https://medium.com/@abdulfayis/storage-orchestration-for-kubernetes-c6370f943e23)
- Source: medium

# Summary

Kubernetes provides efficient storage orchestration by managing persistent
storage resources in a scalable manner, simplifying the complexities of storage
infrastructure with features such as storage classes and persistent volumes...

# Main Points

1. Kubernetes manages persistent storage with storage classes and volumes.
2. It abstracts complex storage operations from developers.
3. Provides scalability, high availability, and flexibility in storage management.
4. Seamlessly integrates various storage solutions with Kubernetes.
5. Automates administrative tasks for efficient application deployment.
```

## Why the tags matter

The tags aren't decoration. They are kebab-case, lowercase, and they match the atomic
notes of my Zettelkasten (`notes/`). So `#k8s` is not just a label, it points at my
[[Kubernetes]] note, and the article shows up in its graph. Every web note I capture
gets linked into the knowledge web without me touching a single wikilink by hand.

Every note also carries `#aiweb` and `#aiweb-<model>`, so I can see at a glance what
was machine-written and with which model. Honest labeling: the summary is AI's, the
thinking is mine.

## Where everything lives

The vault side is simple:

- `articles/webs/` — notes generated by the plugin from web content.
- `articles/papers/` — same idea for papers (there's a dedicated paper prompt with
  summary, main points and takeaways).
- `notes/` — the Zettelkasten. Atomic notes that the article tags link back to.

The plugin side is even simpler: a modal, a settings tab (API key, model, max tokens,
note path), an OpenAI client and the prompt templates.

## What it doesn't do

Being honest here: it only talks to OpenAI-compatible endpoints for now (there's an
Anthropic client started but the flow uses OpenAI). The related-articles operator —
suggesting 3 real, validated articles to read next — exists as a prompt but isn't
wired into the command yet. And it trusts you to name the note well, because that
name becomes the filename.

## What's next

Wire the related-articles and URL-validation operators into the flow, finish the
Anthropic path, and maybe a paper mode that uses the arXiv metadata instead of
guessing. If you want to poke at it, everything is in the
[repo](https://github.com/BorjaIP/obsidian-ai-web).
